# 写给第一次听的人

## 先找到值得讲的那个发现

选一个具体的人和他此刻想弄懂的事。先替他把看完后能说的话写出来，再从素材里找出让这句话站得住的细节。“知道这次更新很重要”还定不了稿。“以前只能看见合计，现在连这个格子加了哪几行也能查”能指导取景，但其中的“以前只能”还需要旧版本的证据。材料只支持当前能力时，直接讲现在能查到哪一步。技术片可以教会一次判断，新闻片可以厘清谁受到什么影响，人物片可以让人理解某人当时的一次选择。把这个具体收获写入已有的 `story_intent.viewer_value`。一个动作、原话或现场声音本身足以收束时，让它结束这一段。

从观众已经看见或知道的事起笔。可以给一张少算了一笔的账单，也可以让当事人先讲一句出乎意料的原话，或者从一个做到一半的动作切进去。往下写时听着上句接。观众现在缺哪一块信息，哪个动作、数值或原话能给他？日期、发布背景、履历在它们会改变理解的地方出现。报道更新，尽早点清谁改了哪一步，并把它接到手上的这个例子。若整段演示换个产品依然成立，回到原件找出产品特有的一步，或缩小选题。

## 画面给细节，口播带人读懂

写关键一镜时，把打算给观众看的东西和嘴上要说的话并排。画面可让观众核对完整公式、表头、名单和出处。声音可以指出该盯哪一处、两件事是什么关系、为什么这个差别值得留意。需要观众自己发现时，先指位置，留出扫一眼的时间再揭晓。必须讲清的对象和因果要听得出来。让“这里”“这说明”在前一句就有可辨的所指。关键数字值得在嘴上再说一次，成排的数字可以由图保留。

把一句话念给一个没看过资料的人听。“合计公式的引用范围存在遗漏”读起来像报告，可以在选区出现时说“框到第三行就停了。车费在下一行。”听者能跟上是谁在做什么。顺着动作可以连着说，到发现差别处收短一句，让画面多留一口气。要保留的专名、数和单位，在听者第一次用得上它的时候说清。口语感来自说话的对象、措辞和停连，片头问好、反复喊“你看”都可省。

以一张可复算的报销表为例。前三笔依次是 120、160、140 元，原合计为 280 元，更正后为 420 元。这段示范只演本地账表。

| 画面给什么 | 嘴上怎么说 |
| --- | --- |
| 同框给三笔支出和合计，停到能找到车费 | “三笔报销，合计才两百八。那笔车费算进去了没有？” |
| 选中合计格，亮出公式 `SUM(B2:B3)`。第三行与下一行保持同屏 | “点开合计格。看，框到第三行就停了。车费在下一行。” |
| 把选区下沿拖过车费，合计从 280 变成 420 | “往下拉一行，一百四十块加回来了。下回核合计，先看框的最后一行，漏掉的那笔可能就在下面。” |

如果题目讲的是文档接口更新，在第一处疑问后就点明与这本账有关的改变，例如“这次更新后，程序能把原表里这个格子的值和公式一起交给模型。公式里究竟加了哪几行？”随后给本地原件。只有确实运行了模型，才能把诊断归给它。片尾回到受影响的人、他如今能做的那一步以及成立的条件。

人物和档案片用另一种写法。可以从“他开口要彩色胶卷。舷窗外，地球还在移。”接到先后两次曝光的照片，让观众找同一处山脊的位置变化。两张照片让换卷这段等待变得可见。同期若录下了索要胶卷的原话，留给本人说。录音没有交代的内心活动不替他说。

## 配音前通读一遍

在本期工程运行 `"$PY" "$SK/scripts/prepare.py" --read-script`。先只读将实际念出的句子，合上稿，用自己的话讲出到底发现了什么、哪条细节让你这么想。条件允许时，把同一份干净稿交给没看过提纲的编辑。单独读稿只能检查文字和逻辑。有意留给画面揭晓的细节，在分镜里看它是否真的可辨。讲查法时，可以换一张表问读者先看哪一格。讲人物选择时，问哪个细节让他改变了对当事人的理解。需要定位才再加 `--line-ids`。自备采访或连续主持素材应以实际录音为准。

| 读完留下什么 | 稿子从哪里改 |
| --- | --- |
| 只记得品牌、人名或“挺厉害” | 找到第一句评价，换成原件上的一个变化，再写这个变化让谁能做哪一步。缺证据就缩小这句话。 |
| 记住了演示答案，说不出片子为何讲它 | 让题眼接到演示起作用的那一步。删去可以放进任意一期的发布背景。 |
| 每句单听都明白，连起来容易走神 | 顺着上一句还没说完的意思开口。把第一次出现的术语换成熟悉动作，长串条件放回画面或拆到需要它时再说。 |
| 说到结尾只剩“值得关注”“意义重大” | 回到开头的实物、问题或选择，让观众能说出此刻多看见了什么。事实已经落地时，在那个动作或自然句尾直接收。 |

改动真正会念出的 `shots[].lines`。给已有素材配解说时，可重写自己的旁白。引语保留原意与措辞，需要压缩时选有上下文的完整原句。修改文字后再做语速和停顿试听。成片用[首次观看](review-ownership.md#首次观看)核对观众实际带走的东西。


### 把观众带走的判断写成一道新例题

解释因果、价格差异或操作判断时，在 `story_intent.transfer_task` 留下另一个片中没演过的例子。例如片里讲“单价降了，账单为什么反而涨”，可以问“下月单价再降一成、用量翻倍，账单往哪走？你先看哪两个数？”把希望观众能说清的推理写入 `criterion`。片中给足原始数值、比较动作和读数时间。独立首看结束后再发题，若答不出，定位观众缺少哪一步证据，修改对应台词和画面。[首次观看与追问](review-ownership.md#首次观看)

## 顶级博主叙事四条铁律（微型悬念闭环 + 包装先行 + 情绪导演）

1. **微型悬念闭环（Micro-Story Loops）**：每 35–45 秒在彻底揭晓上一问**之前**，先埋下一段的新问题、反直觉细节或冲突（例如“代码确实跑通了，但真正的漏洞不在代码里，而在公理第一行”），杜绝中段出现“总结一下 / 以上就是”这类让观众安心划走的**安全退出点（Safe Exit）**。
2. **拒绝书面公文腔与长抽象段**：严禁开场寒暄（“大家好 / 今天我们来聊聊”），砍掉“首先/其次/值得注意的是/综上所述/不难发现”和连续三层“的”字定语；任何连续 28 秒以上的阐述都必须落地到一个真实数字、生活类比或屏幕可见原件上。
3. **包装先行与前 5 秒兑现**：写稿前先用 `packaging.py draft --project .` 拟定 160px 手机信息流一眼能读清的封面钩子，再检查脚本前 5 秒是否直接回应封面悬念。
4. **配音情绪导演与自动审计**：在配音前运行 `"$PY" "$SK/scripts/story_craft.py" audit .` 检查悬念缺口、书面套话与封面兑现，并用 `"$PY" "$SK/scripts/story_craft.py" annotate-moods edit.json --write` 为关键句自动标注 `line.mood`（`hook` / `curious` / `suspense` / `reveal` / `warm`），让 ZipVoice 配音自然产生语速、停顿与临场情绪起伏。
