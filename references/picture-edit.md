# 让动作承担叙事

动手剪之前，把每个口播问题改写成可拍的动作。问“这封信谁签的”，可给出翻到签名处、读出名字、再找原话三个动作。选素材从动作前开始看，一直看到可辨认的结果。保持一次眼神、手势、滚动方向或同一行原文，把观众带到下一镜。文件的局部推近应停在观众可以核对的词上。需要观众读的证据可以停住。

先试一遍没有外加大标题、边栏、徽标和解说条的画面剪辑。哪个动作还说不清，先补真实操作、另一景别或关键原件。全片通用的两栏模板、静态展板加背景循环、每讲一句切一张卡、泛用打字视频铺着长篇旁白，都会让观众只能读屏。新片的第一镜直接进入人、物或待发生的动作。结尾让问题落到一个可核的结果、已知时点或具体后续动作。

关键镜在手机尺寸选好取景时，把 `crop` 同时写入粗剪 cut 和横版正片 `edit.json` 的 shot。例如 `"crop":[384,216,960,540]` 表示从旋正的原片像素 (384,216) 起取 960×540。导出器按该框等比缩放，随后把包装、角标和字幕叠在节目画幅上。框的宽高比应在源像素宽高比校正后匹配交付画幅。沿用整个原件时照常选择 `fit`。

## 把同一对象留在换镜前后

一个总额对应几处真实设施时，可以把含币种和年份的金额钉在同一位置，底下依次切到各处实拍。让观众先读完数值，再从不同设施看出它代表的规模。进入不同统计口径时收走原标签。同一做法适合换机位时保留的方向标、贯穿多处档案的年份，或沿着同一产品型号连续看工序。它在整个画面的固定位置，跟随实物移动的标注用逐镜跟踪。

在横版工程的 `edit.json` 顶层登记带透明通道的单帧 PNG，按成片时间线合成到剪接之后、角标和字幕之前。

```json
{"montage_pins":[
  {"file":"assets/annual-total.png","from_shot":"plant-a","through_shot":"plant-c",
   "at":[0.5,0.28],"width":0.30}
]}
```

`from_shot` 的首帧起显示，到 `through_shot` 的末帧为止，两端镜头都包括在内。可用 `in_frame` 指定第一个镜头内的起帧，用 `out_frame` 指定最后一个镜头内首次消失的帧。每镜都从 0 算。只有一个镜头时，两端填相同镜号。`at` 是 PNG 中心在画面中的归一化坐标，`width` 是 PNG 宽度占节目宽度的比例。叠放次序按数组从前到后，后列的画在上面。局部返修给 `render_window.py` 提供无锚点的底片，它会按同一帧窗重合成。真实切点前、中、后三帧里核对数字位置和遮挡；字幕、亮色背景或转场峰值经过时也要读得清。

## 关键画面的可见时长

在需要观众自主观察的位置，给 screen-plan 的 cut 加 `watch: [开始偏移帧, 结束偏移帧]`。两者从**本镜开始**计数，结束帧不含在内。例如一镜标成 `{"start":90,"end":150,"subject":"站牌","action":"手移开","discovery":"看见周末末班车时间","watch":[18,46]}`，审片复看的是成片第 108 至 135 帧。这个范围由创作者根据原件和关键帧填写，也可用于表情变化、角色反应、原话、字幕阅读或图表。普通过场可直接剪。

常规导出把观察范围与该候选绑定；在工程目录运行 `review.py`，看 `content-check.json` 的 `pace.shots` 和 `pace.viewing_windows`。前者列每镜的片长占比和字幕占时，后者列观察窗口、同时出现的字幕、候选技术报告里登记的重叠转场，以及从成片提取的 390 像素宽首中末帧。缺技术报告时转场项记为 null，需要原速看两端。原速看时从上一镜进入：第一次看的人在何时能找到对象，何时有机会复核？如果结果转瞬即逝，而结论卡在重复上一句，把时间从后者还给前者。人物的犹豫、文件的阅读、音乐的收尾都可能需要长停留，时长由实际观看决定。首看席先看匿名片，再看这些带提示的帧。

## 留哪些字

剪软件报错与恢复时，找到原录屏里三个能读到的东西：提示给出的原因、用户实际改动的字段、软件返回的成功结果。录屏里光标和提示可能相隔很远，尤其是键盘提交后。把提示、参数或返回值从原画面裁出来，与能辨认当前窗口的全貌一起试排。在目标播放尺寸读一遍那个字段；只看清翻译或大标题时，还要调整原件的裁切。可以在不改素材、镜长、文字的情况下，用两种开头比较“先知道在做什么”和“先看到失败”各自传达了什么。[Screen Studio 的局部快速放大示范](https://screen.studio/guide/instant-zoom)

比较仪表、指示灯、标签或屏幕前后状态时，让首看席单独读一次起点，再读终点。反光、摩尔纹或手指遮掉一部分时，先在同一状态持续的原片内找更清楚的一帧，保留实际时码，再试等比例裁近。如果某一位仍读不准，缩小结论的范围或补拍。叠上设计稿里的数字可能让观众误以为看见了原始读数。

完整口播用短字幕。字幕之外，只在观众需要时临时补上身份、数字与单位、原件关键措辞、时间或来源语境。画面已有清楚的字，就移动视线到它，保持原来的上下文。研究笔记、片内素材类别、制作说明、原页出处清单、长署名、示意素材的用途和重复的身份分类放在 sources.md、credits.md 或发布文案。删除“键盘为输入示意”“打字动作示意”“键盘输入示意”“翻阅文件为示意画面”等制作提示。资料日期若关系到真假，第一次出现用短字幕、配音或必要的一行交代。容易让人把资料画面当成本次现场时，选更明确的画面、使用原件或清楚交代时空。许可明确要求片内署名的内容，预先安排合规的片尾或换用适合素材。

逐镜问两件事：遮住外加文字，还能看到什么动作、发现什么？看完字幕后，画面里还有几份同义的文字要读？剪完调出全片每次切点及字层入退场的实际帧，以手机宽度和正常播放速度复看。遇到“来得及读完，但画面不值得看”的镜头，回到镜头动作重剪。

## 工程约定

新工程在 edit.json 写 `"screen_plan": "screen-plan.json"`，从渲染镜头/字层的同一组参数生成此清单。cuts 是主画面的绝对帧区间（start 含、end 不含），每项给出 subject 与 action。overlays 只列剪辑时外加的事实文字，各项为 start、end、text、purpose、reason。purpose 取 identity、archive_date、measurement、evidence、time 或 rights。普通字幕、品牌角标与网页固有原文分别审看。无额外文字写空数组。导出时会查全片帧覆盖、字层用途及常见制作小字。清单无法识别未申报、藏在素材或旧模板里的字，最后必须复核实际视频。素材许可、日期、作者和时码留在公共素材库与本期来源清单。

素材检索先看公共库；查看同一动作的前后镜、真实屏录及其来源。研究范例见 live-action-editing.md。

在 macOS 上，用 `python scripts/check_screen.py "$MEDIA" --timeline timeline.json --plan screen-plan.json --out qa/screen-read.json` 抽查原尺寸画面和放大的底部文字。要看手机宽度下哪些字还能辨认，另跑一次并加 `--view-width 390 --out qa/screen-read-390.json`。这次 OCR 直接读取等比缩放后的整帧 PNG，报告中的 `view.width`、`view.height` 是实际像素；每条 `samples[].words` 留下该尺寸的文字和归一化坐标。原生粗剪可只传含 fps 和相应镜序 cuts 的 `--plan`，抽取各镜首中末帧并定期取样；比较 alternate 时采用其收据中的切点。识别缺字处回看该尺寸的真实画面，再判断是否需要裁近或延长停留。


录资料网页先在正常浏览器处理遮住正文的 Cookie 弹窗、订阅条与“展开全文”，检查操作之前、选中时、停住后和离开时四个画面。阅读视图从可追溯的原始正文或引用节点取材，保存 URL、采集日期、原文和页面选择范围，截掉无关的侧栏。画面上的日期、货币单位与否定词要完整。小屏实看后再把这段录屏登记为可复用素材。OCR 报告中 possible_site_chrome 是复看线索；制作浏览器设置教程等内容时，这些控件本身也可能是主角。

### 在成片逐帧回读数字和单位

已登记 `evidence_read` 的镜头，`review.py` 会从最终编码片提取首次可读帧及其相邻帧、实读揭晓帧、阅读窗末帧和下一项信息的入帧。打开候选 `qa/evidence-01.png` 对着原速听，再在 `qa/content-check.json → pace.evidence_frames` 核对各帧正在显示的字幕与经过的转场。

如果数字、单位或限定词必须一直可读，在该镜的 `evidence_read` 增加 `"readback":{"text":"32.5 kPa","roi":[0.30,0.33,0.62,0.52]}`。框用最终画面左、上、右、下的归一化坐标，紧贴同一行的完整证据，避开主字幕。macOS 的正常审片会把整帧缩到 390 像素宽，再逐帧截这块区域识字，保留实际字形尺寸。其他平台可给 `review.py --ocr-executable` 指定兼容读字程序。单独调用 `check_screen.py` 时带上该版 `--timeline` 和 `--view-width 390`，也能得到逐帧结果。

看 `pace.evidence_readback.checks` 的首次完整识别帧、揭晓前最长连续识别帧数，以及未确认区间。比如预期 `32.5 kPa`，第 13–15 帧身份条划过数字，第 16 帧恢复，`[13,16)` 会单列。点开该区间的 `sample_sheet` 对照前一帧、缺字首末帧与恢复帧，分辨实物遮挡、识字误读或取框过大。先修数字上的遮挡，再按真实阅读窗口重算剪点和口播。时序建议使用编辑标记的窗口，识字结果保留给实际看片时核对。

设了 `min_read_frames` 或 `min_preview_frames` 后，看同一项的 `reading_target`。阅读截止于画面离开或下一项信息出现的较早一帧。假设需要连续 12 帧读数，其中至少 4 帧供观众在旁白揭晓前自己观察，只有同一段同时够长、够早的完整识别才记为 `confirmed`。只设总阅读帧数时，证据最晚可在揭晓当帧进入这段阅读。若时钟容得下这段阅读，但识字结果有中断，`inspect_frames` 会列出需要回看的帧数最少的一处候选窗口和其中的 `inspect_spans`。用附图判断是否需要移走包装或调整读字框。若标记的画面与口播时序本身已经给不出所需帧数，`timeline_short` 会分别写出总停读和揭晓前的缺口，这时对照该镜的 `recut_options` 调整剪点或台词。

## 定位哪一段画面停了很久

`content-check.json` 的 `pace.picture_rhythm` 逐镜列出画面变化帧占比、持续一秒以上的低变化总时长，以及最长三处低变化区间和同窗字幕。也可以对已经编码的候选单独运行：

```sh
"$PY" "$SK/scripts/picture_rhythm.py" 候选目录/candidate.mp4 --report qa/picture-rhythm.json
```

工具在正常帧率解码实际画面，以 160×90 的亮度图读取第 14 至 74 行，避开通常的顶部角标和底部字幕。它同时比较相邻帧与本次停留起点，能把缓慢积累的位移与真正的停住分开。剪点记录两侧的变化面积比例，并带上已登记的转场类型。读数用于定位，在指定时间看原速画面：停住时观众正在读哪个对象，下一句出现时是否看见新的证据？亮度相近的换色、细指针、取景外和很小的运动可能漏检。镜头移动或一直播放动效也会产生变化，动作是否推进叙事仍须看原片。留出足够读数时间的静帧可以保留。

配音准备完成后，`prepare.py` 会把静态图片承载长句或连续静卡的帧段记入 `timeline.json` 的 `still_picture_notes`，此时可以直接换源或编排动作。正式审片从编码后的画面检查每一处符合条件的窗口。单条长旁白、接连换页的静卡（含烘在同一视频里的换页），以及装饰还在动而指定证据区已静止，都可以进入 `pace.picture_rhythm.hold_candidates`。证据区用 `motion_probes` 圈出实际要动的指针、折线或视频窗，注明动作与时段；为连续停留登记的主体区会按成片原帧率复核，微小动作可再回看区域原尺寸。本次采样会在自然停顿处分段，观察约 2.5 秒以上、其中录音覆盖至少 2 秒的窗口。已有逐句录音时按其实际起止比对；旧工程按字幕时钟。静默停读不会仅因画面停住进入这份清单。

新闻与解释片的主编在交付裁决的 `picture_holds` 逐窗填写 ID、`action`（读填 `read`，听填 `listen`，观察细微动作填 `observe`）、`focus` 和 `reason`。画面与关键区域同时停稳可在同一项下审。查看与该窗相交的 `watch` 和同窗台词，从实片确认阅读结束前有足够时间、下一项新信息已经被看见。例如：

```json
{"target":"reading@160..237","action":"read","focus":"滑台停在第七格的刻线","reason":"先用左端零线定位，再读当前刻度；切得更早会把后一步留给猜测。"}
```

画面已经读完、接下来的解释还在重复时，开具对应帧窗的返修票，删减停留或换成下一步动作。修改后，从新版编码和字幕重新取样。使用自定义报告目录时在裁决写 `picture_report` 指向该版的 `content-check.json`。

### 让静态素材跟得上旁白

把被提示的一句话放回原声播放，写出句首观众知道什么、句尾新知道什么。按手头的证据改这一镜，再从前一句连播到下一句。

静图叠了 PNG 时，`prepare.py` 会根据各可见图层的实际关键帧和镜内相机估算停住的区间。比如 24 fps 的 6 秒镜头，箭头在第 12 帧落位，若剩下 5.5 秒还在说话，剪前便可定位到这段。若为该处登记了 `evidence_read`，提醒同时列出观察什么与计划读多久。核对观众读完之后还有哪句话需要新的画面，再决定保留停读、让下一层接上或提前切镜。最终的实物是否在动，仍从带字幕、转场和包装的成片复查。

| 手头的素材和台词 | 剪法 | 何时停 |
| --- | --- | --- |
| 实拍在解释一次操作 | 取到手指接触、装置反应、结果可见的源帧。让旁白跨刀，沿着同一只手或同一个物件切到结果。 | 指针到位后稳住刻度，给眼睛读数的时间。 |
| 一张账单，讲单价、用量和总额 | 让同一份原件留在屏上，用本地 `spotlight-reveal` 先呈现全貌，按实读词逐处移到相应行。 | 每处可单独设停读；最后停在观众能核对结果的位置。 |
| 两份记录，讲“改了哪一项” | 对齐同一行，用本地 `image-comparison-slider` 在变动词上揭开差异。图表可把旧值、变化、结果错时展示。 | 共同基准、单位和最后的两个值都留在画面内。 |
| 人物在解释画外的原因 | 先用表情、动作或环境声建立人物，再把操作或原件铺在讲话上。 | 在需要听语气或观察反应的句子回到人。 |

例如账单的 `remotion_effect` 可直接这样编排。把 `source` 换成本期原件，`focus` 取实际画框归一化坐标。以下台词有“单价虽然降低，用量增加，所以总额上升”，讲到每个数时光窗抵达，让观众有时间在下一处动作前读完。

```json
{
  "effect": "spotlight-reveal",
  "params": {"source":"assets/bill.png", "stops":[
    {"at":0,"focus":[0.5,0.5],"radius":0.9},
    {"focus":[0.30,0.34],"radius":0.16},
    {"focus":[0.66,0.51],"radius":0.16},
    {"focus":[0.72,0.77],"radius":0.19}
  ]},
  "cues": {"stops[1].at":"@bill:单价","stops[1].holdUntil":"@bill:降低",
           "stops[2].at":"@bill:用量","stops[2].holdUntil":"@bill:增加",
           "stops[3].at":"@bill:总额"}
}
```

给句首光窗的全貌与第一个词之间留出进镜时间。需要静读原句、核对数字或听人物停顿时，保留相应帧段，写清读什么、听什么。镜头的问题若是整句一直在重复上一句，压短口播和镜头即可。

## 看叙事在哪一段加快、在哪一段留出阅读时间

在 `screen-plan.json` 的段首镜头上加一个可选的 `section`。直接写这段要完成的事，例如“提出异常”“逐项排查”“看清读数”“人物反应”。这一镜的入点就是段首，直到下一处标记或片尾。只需在段首写一次。下面的分镜先用两次操作积累期待，再把一个完整镜头留给结果。

```json
{"cuts":[
  {"start":0,"end":24,"subject":"表盘","action":"指针归零","section":"建立参照"},
  {"start":24,"end":39,"subject":"按钮","action":"手指按下","cue_frame":31},
  {"start":39,"end":111,"subject":"表盘","action":"指针停在新刻度","section":"看清结果","watch":[12,66]}
],"overlays":[]}
```

按常规导出并运行 `review.py`，打开该候选 `qa/content-check.json` 的 `pace.sections.segments`。每段给出起止帧、各镜按顺序的帧数、中位镜长，以及字幕每十秒起了几条、字幕占用了本段多少时间。跨切点的字幕按实际覆盖分别计时，起条只归入一段。`cue_frames` 标的是分镜预定的动作音点，可以回放对应帧听终混。对登记过的 `watch`，对照总观察秒数 `watch_seconds` 和其中没有 SRT 字幕的秒数 `watch_without_captions_seconds`。没有登记观察窗时，两项均为 null。画面上的原件、标签和口播仍需原速观察或听辨。

在上例中，先顺着 24、15、72 帧的变化看一遍，再从按键前开始回放，确认较长的一镜让人看到了哪一格。若需要同时读字幕和表盘，可以错开字幕与读数，或把前镜已用完的时间移过来。未标 `section` 的整片归为一段。新候选使用随该版封存的完整 `screen-plan` 切点；未封存切点的历史片按对应时间线里的镜头计数，报告的 `cut_source` 会标明来源。一个渲染镜头内部若包含多刀，按分镜列出内部切点可让它们进入统计。
