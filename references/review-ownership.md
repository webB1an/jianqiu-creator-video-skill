# 审片责任与交接

主编在发出同一版候选时，按本片实际内容指名制作人和独立验收人。画面、字幕、事实和声音可以由原有三席兼任。意见记入当轮已有的审片记录，带上候选版本、时间码或附件路径；同一个人制作的修改交给另一人验收。下表用于容易交叉或遗漏的工作。开头兑现、删镜、片尾回报和画面布局继续按[团队审片](editorial-review.md)与[视觉对齐](alignment.md)执行。

| 工作 | 谁制作或修改 | 谁验收，交什么证据 |
| --- | --- | --- |
| 字幕、旁白与独立 SRT | 字幕剪辑按口播断句、对时。撰稿人提供人名、数字和单位的定稿写法。 | 观众席负责校对本版 SRT、烧录字幕和所对应的口播。看首尾、代表性快句和数字，逐项处置技术报告标出的短闪、连句、识别差异。争议发音由声音席复听，写法由事实席定。意见标时码，改完回放该句及相邻句。 |
| 声音的可辨度与听感 | 声音制作人保留分轨，按具体句子、动作或乐段调整。 | 声音席从最终音轨核配乐、拟音与旁白。判断吐字、语气是否生硬、配乐是否贴画面时写明实际试听的设备、乐句或口播位置。只有测量或转写时，主编把客观结果与尚待试听的判断分别记入裁决。用户点名要求解决的听感问题交给能听到该候选的人复验。 |
| 各段动作与转场 | 动效剪辑按镜头登记有意的动作，给被投诉的拖选、推拉等动作定具体帧窗。 | 画面席按各登记窗口从编码片观察连续帧，并原速回看两端接缝。局改时注明重新测过的区间或能沿用的已审证据及其窗外一致性证明。主编按窗口查遗漏。 |
| 本版素材、署名和用途 | 素材经办人把实际用到的镜头、照片、音乐、拟音、封面图对应到原件、作者、使用条件和署名位置。 | 画面席核画面和封面，声音席核本版实际用音；事实席在可能混淆时核身份、时间、地点和示意标签。复用旧工程或换素材后，从新剪辑与混音倒查清单，去掉只属于旧版的条目。另行分发原素材或写入可迁移包时，检查该用途是否在已记录条件内。 |
| 三种封面及其标题 | 封面制作人按各画幅单独裁切、排字。 | 观众席打开候选附带的 16:9、9:16、3:4 三张成品，以缩略图大小读标题、看主体。事实席对封面中的人名、数字、档案年代与标题暗示负责。涉及具体画幅时，在意见中写文件名和受影响区域。改封面后用新附件开轮复核。 |
| 局部返修和关闭票据 | 主编在决定修改时明确谁动手、谁独立复核；修订人交新候选和实际修改区间。 | 复核人按原票的可观察条件回看原区间和接缝。时基改变时交代旧窗如何对应到新窗；主编核对执行人与复核人的交接记录，再关闭问题。票据字段见[团队审片](editorial-review.md#操作)。 |
| 交给用户的文件与重建入口 | 主编或其点名的交付人公布已签版，整理本次承诺的附件。 | 从给用户的入口打开正片、SRT、三张封面、来源、纪要与工程说明。用 verify 核对已签媒体和配套文件的版本，再检查说明里的本地路径、跨工程的脚本和素材依赖。声称能独立迁移或已从头重建时，要有对应环境的实际验证。有来源或工程附件错配时交经办人补正，再从同一入口复查。 |
| 可复用经验回写 | 主编确定本期哪项反馈有复用价值，点名对应工种维护规则、组件或素材条目。 | 由另一位审片人用旧失败样本或第二个输入复测；在研修或资产记录留下用途、适用边界和测试结果。更新可迁移 skill 时，维护人从打好的包复查改动和必要资源。 |

字幕或封面文件本身的版本由候选凭据绑定。片外署名、工程依赖和试听条件由指定人员检查并记录。对于只有附件的问题，直接标注文件与版本，按受影响的附件复核；画面或音轨上的问题才按实际帧窗定位。

## 首次观看

关键揭示能否看懂或听清，先由普通观众席回答。以听觉为主的题材首看时带声原速播放。让听者复述自己听出的变化，分清现场声与讲述者的判断。涉及空间或图表时，再让观看者指出具体位置。主编把待审 MP4 交给没看过脚本、早期剪辑或预期答案的人，只发匿名目录和一个中性问题，如“看完后什么给你留下了印象？从哪儿看出或听出来的？”可用 `--question` 指定适合此片的问法。先封存原话，再给脚本和要核实的帧窗。看过提示的人可以复核修改，登记时如实填写此前是否知情。

用 `blind_review.py first-view 本版.mp4 --folder 新目录` 生成 viewer。回执填写匿名任务中的 files、reviewer、unbriefed、method（原速播放、静音或抽帧等）、observation（观看者的原话）、status（located、uncertain 或 missed）及 limits。能定位时写 location，记得出现时间时可写 at_seconds。用 `blind_review.py record 回执.json --folder 新目录` 封存原话，再用 `blind_review.py result --folder 新目录` 读取。主编按片的实际版本对照分镜预期，区分指对位置、复述旁白、只认出提示框和确实看见画面差异。若首看席缺位或只看了抽帧，要在纪要注明证据范围。

让实际拿着手机的人首看时，给上述 `first-view` 加 `--device-page`，将生成的 `viewer/device.html` 作为一个文件在支持本地 HTML 的浏览器打开。它内嵌匿名成片，可按手机实际大小播放、记下观察原话、设备、声音方式及片内位置，保存 JSON 后用同一条 `record` 命令封存。若系统只显示静态预览，用系统播放器打开同目录的 `film.mp4`，按同一问题记录原话。观看者填写设备与限制，页面记录播放过的区间。要核实播放器按钮、标题区遮挡或平台转码，使用该版本的真实平台草稿或播放页，并按[投稿复盘](social-handoff.md)另存观察。

## 跨题材对照、听审与事实范围

只想判断一个剪点的作用时，固定源画面、音轨和其余参数，只改待比较的一项。用 `blind_review.py prepare 旧版.mp4 新版.mp4 --folder 新目录 --question 阅读或听辨任务`。每位审片者只拿 viewer 目录，先独立回答 A、B、持平或无法判断，并注明观看尺寸、耳听条件或测量方法、双方可观察的区别及局限。用 `record 回执.json --folder 目录` 逐一登记，再用 `result --folder 目录` 揭盲。若两版同时换了开头、旁白和时长，回执用于比较整版体验，单个改动的作用需另做单变量试剪。回执字段为 files（匿名题目内两个文件的 SHA-256）、reviewer、method、observed_a、observed_b、basis、preference、limits。ASR 能核对字词，编码响度与分轨差值能说明信号；声称实体手机外放、耳机辨认或真人偏好时注明实际设备与听者。

准备后的新片会登记标题、封面、数字口播及量测叠字。普通定性断言、录音与稿件不一致、已绘制在画面里的图文等需主编逐镜补录。`edit.claims` 的每项写 id、surface、text、source，可加 shot。例如在 chart 指定某镜“960 个采样点”，来源写 measurement.json。核稿者对照冻结字幕、实际说法、图表和三张交付封面，检查单位、原句及限定。引用原件或音效/BGM 时同时核验来源附件、署名、许可适用范围。

### 原速声画对照

用上面的 `prepare` 生成两版，打开 `viewer/index.html` 即可本地播放。首次比较时让每版以 1 倍速从头播到尾；有两位审片人时可交替从 A 或 B 开始，先记独立意见。回看动作、口播和音乐的关系时，可切到另一版的同一时刻，或回听前三秒。记下具体出现的词、音乐起落、动作以及片内时码。若两版时长或结构不同，改用各自对应事件的时码。

在有 Chromium、Node 和 puppeteer-core 的机器可验证播放器正常工作。运行 `node "$SK/scripts/verify_playback.cjs" 对照目录/viewer 新报告.json B A`。已安装 Chromium 的路径可用 `CREATOR_CHROME` 指定。它读取实际带声音的 MP4，在浏览器以墙钟时间播放两遍，记录每版播放覆盖、媒体时钟、送显帧、掉帧和设备输出前解码的 PCM 能量。测量回执留在技术证据；判断听感时另记实际听者、设备及所听片段。

## 看懂了示例，能否讲出整条片

立项时先在 edit.json 写 `story_intent`。有具体事件或解释任务的新片从受众实际关心的变化写起，人物、档案和观察片可以写一种认识、疑问或情感。一条科技新闻需要说清谁发布了什么、相较过去有哪些可核实的变化，这会影响谁、在什么条件下能做什么。演示中的一次成功只支撑它实际展示的那部分。若删去片名或把主角换成同类产品，全片依然同样成立，重写事件与示例之间的连接。观众能自行找出表里漏加的一行，只能证明示例讲清了。标题、开头和片尾承诺了某项发布时，审片还要听到观众怎样复述那项发布。

例如，假设社区新开了夜间读者预约取书柜，`story_intent` 可以写成下面这样。

```json
{
  "story_intent": {
    "kind": "news",
    "main_point": "社区图书馆新开夜间取书柜，已预约的书闭馆后仍可领取。",
    "viewer_value": "晚班读者可以提前预约，下班后取书。"
  }
}
```

人物片可把主旨写成“搬离老家前，母女一起补好了父亲留下的旧雨衣”，收获可以是“从母亲把针递给女儿的停顿，体会她怎样把不舍说出口”。保留观众意料之外但有声画根据的读法。注意力原话要记他们在何处开始想往下看、何处走神或想退出；没有明显波动也可照录。观众从片尾才弄明白为什么开头值得看时，对照最先提出的问题、第一次给出的证据和转入正文的剪点；必要时把证据移到第一次可能划走的位置。

1. 登记候选并冻结意图。运行 `blind_review.py first-view 本版.mp4 --story --folder 新目录`，可加 `--device-page`。只交 viewer，不透露题材预期、标题稿或目标受众。新的中性问题在 task.json 的 story_questions 中。已有的 observation、location、limits 照录，补上观看者原话 main_point（整片讲什么）、viewer_value（本人理解或感受）、attention（具体在哪儿想看或走神）。按实际填写 playback：continuous 为原速从头看到尾，sampled 为抽帧或跳看，partial 为只看片段或变速。音画是否都可感知仍记在 method 和 limits。
2. 在发脚本前用 `blind_review.py record 回执.json --folder 新目录` 封存。`editorial_review.py first-view 本版.mp4 --trial 新目录` 从已登记的匿名任务直接导入回执，核对问题与片源散列。加入新回执会重开尚未裁决的会议。抽帧与知情复核可作为补充；整片叙事判断至少需要一份未受提示、原速连续看完的原话。音频承担叙事时用有声回放。
3. 主编对照导出的意图、片中具体例子、全部符合条件的原话与观看限制。在会审 JSON 的 `story_readings` 中，每位填写 reviewer、main_point 和 viewer_value（分别写 matched / partial / missed）、attention（keep / revise）与 basis。basis 说明哪句原话对应哪项变化，哪个镜头维持或失去兴趣，以及该时刻为何值得保留或返修。观众没兴趣和没看懂可以有不同的判断。复述一个型号、一个热闹动作或一道算术题，还没说清全片的核心变化，就把差距如实记到对应项。
4. 原话支持主旨与价值，且吸引力判断可保留，才进入签发。缺失、片面或观众指出必须修的掉点，写票退改或暂缓。重剪后另找未看过早期剪辑的人首看。只修片外附件、影片字节和意图都相同时沿用原回执，三版封面和 SRT 仍需复核。本轮有明确叙事意图时，status 的 missing_editorial 列出尚缺项目。旧工程缺少 story_intent 时沿用既有审片记录和验证方法。

观众只说出“挺有用”时，主编在原话和候选中找真正被记住的那处细节。若观众记得查出了哪一笔错误，却说不出这件事如何说明题目里的变化，返修票指向连接两者的镜号和台词，回到[写稿与读稿](video-writing.md#配音前通读一遍)改那一句，再按同版成片复核。依赖图表读数的内容也要查看对应帧。

完整会审摘录的字段如下。此例用预设原话说明判读格式；制片时使用当轮导入的真实记录。

```json
{
  "story_readings": [{
    "reviewer": "该片首次观众",
    "main_point": "partial",
    "viewer_value": "missed",
    "attention": "revise",
    "basis": "观众记住了扫码开柜，却以为白天也必须来柜台排队；第一镜关灯后仍能取书的变化，到片尾才被看懂。"
  }]
}
```


### 首看封存后追问一个新例子

有 `story_intent.transfer_task` 的片子，先照常封存并导入同一版的无提示连续首看。再把 `question` 单独给其中一位观众，保留回答原话，主编保管 `criterion`。报告含 `candidate_sha256`、`reviewer`、原题 `question` 和原答 `answer`，用 `editorial_review.py transfer 候选.mp4 回答.json` 导入。会议在这位观众的 `story_readings` 写 `transfer` 为 `matched`、`partial` 或 `missed`，在 `basis` 指出回答能解释或遗漏的那一步。缺答或未掌握时退改；让新观众复看新版本。
