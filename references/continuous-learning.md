# 动效研修与实拍素材

## 自主选材与回写

**每次制作。** 围绕本期问题先从个人库找声画和内容。查到研究笔记就打开原文，查到剪辑卡就看预览与已有审片结论。在现有分镜、素材清单或制作笔记中记下采用的条目、用在哪一镜及还要补什么。搜集外部素材和剪片过程中，agent 自己处理值得留存的成果，也可以选本期最终剪掉、但用途清楚的候选。用户给文件夹时检查本次相关的文件；只给主题时按库内缺口自选来源。

**多位创作者研修。** 用户指定平台、方向、人数时按这些条件挑不同的创作者。例如“去 B 站学至少五位科技博主的转场”，要实际看够五位不同创作者的相关片段。同一作者的多个账号或同一作品的搬运按同一来源计。片段无法播放时在指定范围内换一部或换一位，最终说明实际看到了多少。普通制片的选材量由本片需要决定。沿用研修记录按作者注明作品原页、时间段、具体看到或听到的做法，链接到对应库条目或 skill 小节；几位作者展示同一种剪法可共同指向一份自制示范。在研究卡的 `editorial.applications` 列表里填 `{"id":"库内示范ID","role":"在该示范中看哪一刀"}`。有明确的制作方法时，可将方法说明作为同卡附件，以 `{"file":"附件标签","role":"使用时要判断什么"}` 关联。标注只是技法迁移还是本片确实采用，库内示范保留其自身的使用范围。普通取用或项目检索时打开给出的示范或附件。

**怎样选和放。** 判断下次做哪类镜头会用到它，以及现有条目还缺哪种动作、角度、声音或解说依据。实拍、录屏、原件、拟音、环境声、BGM、转场和可编辑动效归入各自类别。可复用的内容也收，例如一段能查回出处的解释或一个有效的前后对照结构。外部作品的剪法用自己的观察笔记记录作者、链接、时码与使用范围；可用自有或获准素材复做的技法，做成可预览、可替换输入的制作卡。涉及报道的原件保留语境和日期。一次性的题材资料随项目保存。

**怎样算落实。** 按用途、作者、原始来源和可用时间段查重，遇到改名副本再比文件校验值。相同条目沿用原 ID；同一条有了新叫法就合并搜索词，有实质改进就修订并保留旧版。用[素材库入库命令](media-library.md)登记，核验原件与预览，再用日常用语实际搜一次。对会改变下一期制作判断、并已在试剪或审片中验证的经验，更新对应步骤或组件；有正式候选与审片记录时可回写所选卡。交付时简要给出复用和新增了什么、怎么搜，以及改了哪条方法。已有内容足够时照实说明，可以零新增。

## 深入拆解与试剪

单独维护技能时，将已有原片的观察直接转成可复用的制作指令、参数或工具，针对改动做代码与数据核验。以下试剪步骤用于用户委托的制片、重剪或样片制作。

从上期最具体的一处剪辑问题开始，例如观众能读到数字，却没看清分母。查看当前工作区 learning/index.md 和相应项目 qa。先选择能直接验证的一项改进。

1. 对照所学工具的官方文档和一个实际播放的创作者片段。记录版本、作者、作品、公开 URL、可连续观察的时间段、取样率、主体在起中末帧的位置和切点两侧的关系。有音轨并实际听辨才能记录乐器或声音设计。封面、脚本、稀疏缩略图只能帮助找到待看的位置。
2. 用自己的内容或有授权的照片、实拍视频重做。先定前后两镜是否有共同对象或运动方向，再选匹配剪辑、分屏、遮挡揭示、图形变换或直接切。写清观众应该在什么时候看哪里。对一份真正需要读的公告，留给观众读完的时间。
3. 让新资产支持不同素材、时长和画幅。以两个不同输入检验寻帧、极短镜头、重复渲染和最终停点，实际解码。把适用的脚本、短样和调用方式写回 skill。避免把参考片片段装进分发包。在 learning/index.md 记录能重用的能力、证据、实测限制和下次待解决的问题。
4. 为每段实拍记录谁、何时、何地、可见动作、允许的用途、入出点及署名。历史资料在档案清单登记年代地点；若混淆时空会改变理解，在首次出现时用必要的简短信息交代，或改选画面。同一人多段实拍优先选能完成不同任务的动作。对比人物、机构或数字时，可让两路资料片同时播放，再把观众注意力交给其中一侧。
5. 在生成画面的步骤顺手写 footage-usage.json。数组每条含 shot、start_frame、end_frame、source、kind、source_url 和 license。帧号以该镜头入点为零，含起点、不含终点。kind 为 video（原始影像在播放）或 photo（照片或定格）。只填看得清的素材。原创图形、纯色或泛化纹理留空。运行 scripts/footage_audit.py，得到照片、实拍和两者并集的时长；它计算标记区间的并集，分屏同帧只计一次。审片者仍需核实这些帧实际可见、身份与字幕相符。
6. 镜头复核通过后验证 skill 元数据、核对包内脚本与资源，再更新项目导出包。下一次制作优先调用已经测试的组件。用户明确需要对比样片时随研习记录交付。

### 从一部新作品学到可复用的剪辑判断

先在研修索引去重，针对上次退片的具体问题选作品。记录作者、原片链接、观测精度；梳理从提问到兑现的段落后，回到剪点前后连续回放。把“在什么时码看见或听见什么”和“我推测这样剪是为什么”分开。帧间丢失的地方只记可证实的先后。每条可迁移做法都配一个误用或失效情形，例如没有真实分组时不能把总数动画拆出虚构份额。

在受托制作的项目里，用自己的材料剪一组可看或可听的对照，让独立看片人先复述看到的区别，再看制作意图。确有改善则改动对应的导演步骤、组件或签发条件；没有证据或结果更差时在项目研修记录留下舍弃理由。下一期再次遇到同类场景复测，有观众反馈或发布数据再补入。资料清单、创作者片段和一次性研究图留在项目，分发包只带能帮助下一期选择镜头的做法。

## 让下一期搜到使用效果

开片在本期工程分别查主题、内容和动作。素材搜索会查许可范围、原件正文、旧审片笔记和跨片试用结果。打开命中条目的原件和已有笔记；旧经验针对当时的卡版本，新的素材与信息量仍需实看。对实际影响本镜的一项写下采用、改编或舍弃及理由。普通选材无需逐个登记落选结果。

```sh
"$PY" "$SK/scripts/project_learning.py" --project "$PROJECT" find 阅读
"$PY" "$SK/scripts/project_learning.py" --project "$PROJECT" decide "$CARD" --lesson "$NOTE" --shot "$SHOT" --action adapt --reason "$WHY"
```

`find` 会给出具体的 `卡ID/笔记ID`。跨片试用结论也会给出 `result/卡ID/结果ID`，下一期可以直接把它作为 `--lesson`，同时保留上次的适用范围和实测依据。`decide` 返回决策 ID。素材库直接使用的文件仍用 `library.py use` 或 `visual_case.py select` 提取。选择后有意换掉本期项目副本中的文件，用 `visual_case.py derive 卡ID --project 本期 --cut-start 入点帧 --reason 改动理由` 登记；同一卡的旧项目可独立重建。随候选冻结使用决定和登记过的项目文件校验值。

同一镜的口语没有命中时，agent 用 `find --shot` 记录原句和换词后的查询。选中素材并看过原件、确认主体、动作、方向和限定条件都符合原句后，在本次 `decide` 加 `--confirmed-query`。例如：

```sh
"$PY" "$SK/scripts/project_learning.py" --project "$PROJECT" find --shot focus "近处的圆片退成模糊的影子"
"$PY" "$SK/scripts/project_learning.py" --project "$PROJECT" find --shot focus "焦点转移"
"$PY" "$SK/scripts/project_learning.py" --project "$PROJECT" decide atlas-camera-rack-focus --shot focus --action use --reason "已看预览，镜位不动，近处圆片先清楚再变虚" --confirmed-query "近处的圆片退成模糊的影子"
```

后续换词命中的结果会列出同镜早先的空查询。只有实看确认的那句会成为卡片别名。合适的替代镜头仍可正常选用，原句对应的动作仍缺时保留为空；舍弃或仅搜索的记录也保留在本期。下一个工程再用原句检查取回的卡片。

正式审片讨论完成后，从评过的候选和实际镜头观察回写结果。遇到仅试验一种剪法的场景，给独立审片者看匿名对照片，再按这次试剪的范围留结果；小样与正片签发分别保留证据。用下列命令回写，再用另一工程的本期检索词实搜一次。素材库网页展开卡片也能看到跨镜使用效果。

```sh
"$PY" "$SK/scripts/project_learning.py" --project "$PROJECT" outcome "$MEDIA" "$DECISION" --assessment supported --reason "$OBSERVATION"
"$PY" "$SK/scripts/project_learning.py" --project "$PROJECT" trial-outcome "$MEDIA" "$DECISION" --trial "$TRIAL" --shot "$SHOT" --reason "$OBSERVATION"
"$PY" "$SK/scripts/project_learning.py" history "$CARD"
```

直接试验实素材镜序时，先给计划中实际存在的镜号用 `decide` 选卡。用带 `--project` 的[双版粗剪命令](run.md#实素材粗剪)输出两版，再以 alternate 作对照、first 作候选送匿名观众。当观众提交回执后运行下面的命令。结果中的 roughcut 会保留两版镜序、该镜实际源时间窗与前后位置。若只给观众看了一个版本，可留首看原话，比较镜序需要观察同一对文件。

```sh
"$PY" "$SK/scripts/blind_review.py" prepare "$CUT/alternate.mp4" "$CUT/first.mp4" --folder "$TRIAL" --question "$QUESTION"
# 登记独立观众回执后
"$PY" "$SK/scripts/project_learning.py" --project "$PROJECT" trial-outcome "$CUT/first.mp4" "$DECISION" --roughcut --trial "$TRIAL" --shot "$SHOT" --reason "$OBSERVATION"
```

## 修改公共方法后发布

在 video-shop 工作区，实质改变公共步骤或代码时，agent 自行构建候选、运行同一组旧片及固定故障用例比较两版，并查看逐项结果。涉及风格、阅读或听感的改法，还需有相应的独立观看或试听依据，应用范围限定在实际检查过的任务。可保留失败案例或单卡笔记，再遇到合适题材复测。常规补素材只更新个人库。

```sh
python3 learning/package_skill.py build
python3 learning/package_skill.py assess candidate --suite learning/reliable-editing/regression_suite.py --python "$PY"
python3 learning/package_skill.py promote candidate --assessment "$ASSESSMENT"
```

评估回执包含两份归档和同一组测试的标识。候选验证通过才提升为稳定版。要恢复旧版，先用 `status` 看版本、用 `checkout previous --into 新目录` 核验；执行 `rollback previous` 切回登记的稳定版本，再用 `install stable --into "$SK"` 恢复本机安装。`build` 在版本归档里生成候选。需要一份独立试装包时用 `build --candidate-output 试装包.zip`；验收并执行 `promote` 后才更新工作区常用的 `creator-video.zip`。
