# 剪一段观众能看懂的动作

先把旁白和叠字关掉，只看主画面。挑出能说成“谁在哪儿做了什么，结果怎样”的片段。记下源片入点、动作转折、结果和出点；例如手伸向纸页、纸边被掀起、下一页落平。让观众至少看到被讲述的那个变化。手还没碰到纸就切、素材始终垫在遮住主体的文字下、靠换一张无关实拍才能继续讲，都值得回到素材里重新选段。

## 按同一动作点比较候选原段

两段素材都符合检索词，却很难决定用哪段时，找一个可见地标对齐两者。例如分别定位卡扣第一次闭合的原帧，或报错第一次出现在屏幕上的原帧。把上镜结束时的视线落点带进选材，在预计取景里看手势是否挡住卡扣、握持方向是否接得上、观众能否看到动作的后果。若下一刀还需要借源帧做转场，将余量限制在这次动作确实仍然连续的范围。

在项目中写 `takes.json`。以下例子假定两段原件都是朝上显示的 1920×1080 视频。帧号按各自源文件的解码显示顺序从 0 起算。`usable_frames` 的末帧不包含在内，可以用它排除机位晃动、卡扣被遮住或切到别处的部分。`contact_frame` 是动作发生的源帧。文件路径相对清单。

```json
{
  "target": [1920, 1080], "fps": 30, "phone_width": 390, "window": [12, 24],
  "takes": [
    {"id":"全景","file":"assets/bench.mp4","contact_frame":68,"usable_frames":[50,101],
     "crop":[0,0,1920,1080],"eye_trace":"沿上镜桌面右侧的插头找到卡扣"},
    {"id":"近景","file":"assets/latch.mp4","contact_frame":109,"usable_frames":[102,142],
     "crop":[320,144,1280,720],"eye_trace":"对齐右侧卡扣，留出手指松开的空间"}
  ]
}
```

```sh
"$PY" "$SK/scripts/action_takes.py" takes.json
"$PY" "$SK/scripts/action_takes.py" takes.json --view qa/动作并排.html
"$PY" "$SK/scripts/action_takes.py" takes.json --view qa/听近景.html --listen 近景
```

`target` 为交付尺寸。`crop` 的四个数依次为左、上、宽、高，单位为元数据旋正后原视频的栅格像素。源像素宽高比会参与匹配。省略 `crop` 时取居中填满目标画幅的区域。`window` 按目标 fps 填写接触前的帧数，以及从接触帧算起想看的帧数。脚本从每个原件的真实显示时间戳取样，所有候选共用均有余量的一段；例如同为 30 fps 时，上例近景能提供接触前 7 帧，预览的第 7 帧便是两个角度各自的闭合瞬间。

默认输出列出候选的源时码、可用前后秒数、裁切框、放大倍数及源音轨。`--view` 写出单文件离线上屏对照，浏览器按清单顺序并排播放，单格默认 390 像素宽。`--listen` 同步播放画面，单独听指定原件的第一条音轨。静音看一遍动作，再独听两条素材，分辨现场反馈、画外噪声和后来配入的音乐。不同候选的原声可以各留一份对照页。选材预览只含选中的短窗口。

接触前看能否顺着上镜找到目标，接触后看结果何时变得可辨。`max_axis_scale_to_target` 超过 1 时，至少一个方向要放大源像素，可在交付尺寸复核卡扣边缘、表情或原字。选定后，将报告中的 `crop` 用在分镜和正式镜头中，沿用原件的实际入点与时长。在该镜选卡记录里记下动作帧、前后余量以及这一角度真正补充的信息。[工程编排](run.md#实素材粗剪)

## 六种剪点

| 哪里需要换镜 | 源片里能看到的动作 | 换到自己的素材 |
| --- | --- | --- |
| 观众要看见障碍或结果 | Casey Neistat 骑车时，镜头从侧面跟随。前轮与路障进到同一画面，路障遮住车身后，才换至另一个路口。[《Bike Lanes》，01:22–01:29](https://www.youtube.com/watch?v=bzE-IMaegzQ&t=82s) | 挑能同时看到动作发起者和目标的实拍。出点留到两者相遇、动作确实改变之后。前后镜来自不同事件时，只连动作或话题，别把空间关系剪成虚假的现场因果。 |
| 需要让观众自己找到一句原文 | 何同学把设备旁工作的人切到库克传记封面。页翻开，镜头站住，荧光色才沿印刷行方向展开。[《After Genius: The Tim Cook Era》，03:22–03:35](https://www.youtube.com/watch?v=IR5rTZMsdIE&t=202s) | 让人先认出原件，再追踪其中一行。实体翻页接原件时，匹配页边运动方向；网页就用真实的滚动、点开或选中动作。读到目标后定住，让字形可读。 |
| 开阔场景里需要换视角 | 影视飓风先在走道上向前赶，一转视角出现头戴设备的拍摄者，随后会场和人群绕中心展开，回到贴近身体的视角。[《全网最高画质第一人称逛展，会拍到啥？》，00:18.5–00:22.7](https://www.youtube.com/watch?v=YP0IIKcdT2A&t=18s) | 从“他看见什么”换到“他怎样看”时，两镜保留一名人物、一件设备或能辨认的位置。特殊镜头只在素材的空间关系足以支撑时使用。普通新闻素材也能用一次抬眼接其观察对象。 |
| 大远景交代过位置，动作细节却太小 | Mark Rober 的院子远景里有松鼠在高处跨越，切俯视看它经过板上机关，再贴近双爪和嘴部；景别变，松鼠始终是可辨对象。[《Backyard Squirrel Maze 1.0》，00:16.5–00:21.5](https://www.youtube.com/watch?v=hFZFjoX2cGg&t=16s) | 用远景回答“在哪”，用近景回答“哪一处正在动”。只有近景确实补上信息才换；判断切点时看主体、动作和方向是否还能被追踪。 |
| 运动已经发生，需要解释它走过哪里 | Tom Scott 身后出现橙色轿厢的横向运动，再切到两条轨道收向远处的视角。先看到移动，才有理由看路径。[《An elevator that actually goes sideways》，00:09.5–00:13.1](https://www.youtube.com/watch?v=kdTsbFS4xmI&t=9s) | 先给运动能被看清的侧面或中景，观众产生疑问时再沿路径换角度。墙面、桌沿和画面中的实线都可帮助定位。 |
| 有一个差异必须让观众亲眼发现 | The Slow Mo Guys 从主持人身旁的电视切至屏幕，先是大块噪点与暗带，随后高速拍摄显示出逐次扫过的亮线。观众凭同一个发光表面辨认对象。[《How a TV Works in Slow Motion》，01:42–01:53](https://www.youtube.com/watch?v=3BJU2drrtCM&t=102s) | 对新闻页面可以用原件的两次取景：一次解释页面在谈什么，一次看清限定词。实验类则应优先切到真实观测。对影响解释的条件或单位给一个可读提示。 |

## 在两个镜头之间选转场

先在时间线上试一次硬切。手从中景接近景时，对齐接触前后同一动作阶段，避免观众看到手再伸一次。视线剪辑先留出看向某处的瞬间，再检查反打里的目标是否落在能顺着眼睛找到的位置。人物出画再入画时，检查行进方向、速度和新空间的交代。

下一场的声音能交代地点时，可在画面切过去前先让它出现。原话需要保住句尾或当场反应时，把旧声音留到新镜头。明确跳过时间时可试叠化，检查两幅画面重叠的那一刻会不会把两个读数叠成第三个。需要做风格化转场时，优先取本镜真实经过画面的遮挡物或运动边缘，比较硬切版和效果版，原速能更快找到下一镜主体的方案优先。

## 使用时留意

- 当正文在讲一个人，先看手、脸、身体或环境怎样变化。可以留没有额外文字的实拍。人名只在需要辨认、且观众尚未从旁白和画面得到它时短暂出现。
- 用现成素材前记下最有用的几个可见动作与源时间码，而后按真实口播选取。结尾即使留一张文件，也应让前面的问题在那一行得到答案。已经解决问题的镜头可以安静停留。
- 审片时播放同一段两遍。静音看能否说明“为何从 A 切 B”；开声看落点是否跟着口播与可见动作。若换成一张静帧后丢失的信息很少，优先寻找动作本身承载信息的镜头，或把重复段剪短。

## 让转场中的动作继续走

选前后确有同一动作的两段原件。先定新镜的入点和前镜的出点，再到原件向两端多看几帧。若叠化时人仍在抬手或滑台仍在移动，把转场写在**后镜**的 `transition` 字段。比如 30 fps 下：

```json
{"id":"closer","visual":"assets/carriage.mp4","in":1.2,"transition":{"name":"focus","seconds":0.4,"handles":"source"},"lines":[{"text":"从这个角度，能看到它越过刻线。"}]}
```

这一段 12 帧重叠从原剪点前 6 帧开始，到剪点后 6 帧结束。前一个视频保留 6 帧实际后续动作，后一个视频从计划入点向前借 6 帧；剪点时后镜仍到达原先选定的源入点。其他镜头、旁白和字幕沿用准备过的时间轴。遇到素材余量不足，改选有余量的入出点、缩短重叠，或在接触帧直接切。转场一端是图片时，该端继续显示原图。旧工程省略 `handles` 时，拼接器维持其原有的边帧停留。`focus` 是短叠化；`page` 和 `glide` 分别以纵向和横向边缘擦入。对齐刻度、账单金额或按钮文字时，同时显出两个读数可能影响判断，应对照硬切版本。

对照时优先复看动作开始、运动穿过剪点、效果结束三处。轨迹能否连续，要看原片物体是否真在走；只有动画边缘移动的擦拭，依然可能盖着两个静止主体。为一份长口播换镜时，在一句话里寻找动作发起、对象变化和结果出现的时间，尽可能从连续源动作里切出相称景别。需要观众读档案、听一句原话或判断结果时，保留相应的静止和停顿。在 `technical.json` 的 `transitions` 可查转场实际帧窗、原剪点及两端借用的源帧数。

相邻面板向左交接用 `push-left`，沿竖向列表进入下一节点用 `push-up`。两种推移都能配 `handles:"source"`；前后原件留够帧数时，移动中的主体会随接缝继续运动。同页定位一个错误或一个端点时，可直接推进到局部，把视线留在原件上。
