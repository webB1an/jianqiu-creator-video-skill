# 一条解释片怎样从材料走到成片

针对当前引入的 wallstreet-explainer 版本 `f39845a`，按观众此刻要弄清的事情选择下面的入口。无主持人时，人物、仪表、实物、现场动作或有出处的原件可以成为贯穿物。有连续口播时，可以让表情承担提问与表态，把事实交给现场或图表，再回到同一个人。见秋日常横版的字幕、字号与色义、声音和签发流程适用于这两种制作方式。[参考版本](https://github.com/HeyChengC/wallstreet-explainer/tree/f39845abd45dab3c9ce62587aa5d02f6afe82612)

## 从开头的第一眼排到最后一镜

| 有什么材料 | 第一眼怎么给，下一刀接什么 |
| --- | --- |
| 一个极端的数或一个不容易想象的尺度 | 先出有单位的总量，随即折算成一个真实的日常量；或让同一画面里的已知实物给出可见的参照。 |
| 两项本该相近的结果却相差甚远 | 同一坐标或等面积标准下并置，让观众先看到差距，再回原件找原因。 |
| 一句有力的当事人原声 | 从关键原句起，保留听清句意所需的上下文，接回这句话影响的具体对象。 |
| 许多出处反复提到同一词 | 可以把真实原件上的词定位在同一屏幕位置，周围的出处依次换；也可以让标题墙先铺开，再留下最能回答问题的一条。看清后给出这份原件。 |
| 最后一步很反常 | 先给可以验证的结局，留下成因，回到起点。若问题是「转了一圈去了哪里」，沿真实关系走完线路再揭晓终点。 |
| 正片有几个一眼可辨的动作 | 从本片抽取短预告，每一格要能认，最后一格延伸到正片第一件事。 |

在分镜的每一个重要边界写三件事：上一镜刚看清的对象、下一镜第一次能认出来的对象、把两者联系起来的动作。导演可以先排不同机制的开头，用本片第一句与第一条实证选定有把握的一种；交付节奏服从用户这次的要求。结尾再回到开头的原物、原句或原画面时，让观众指得出自己刚多知道了什么。[作者的开头选择](https://github.com/HeyChengC/wallstreet-explainer/blob/f39845abd45dab3c9ce62587aa5d02f6afe82612/references/opening.md)

## 从导演表找到制作入口

| 做到哪一步 | 在见秋工程里的做法 |
| --- | --- |
| 找现场素材、定位动作与同期声 | 先查个人库，核出处与可用区间，按动作点比较镜头；预裁帧序列要带回源帧号和 PTS。[选材、分层、声音与运动检测](wallstreet-craft.md) |
| 要交代网页出处 | 原页先交代来源和条件，随后逐行刷出真实原句，等读完再换场。遮挡或页面改版时重新测量。[网页实测取句](screen-and-mix-review.md#把网页原句做成证据镜头) |
| 数字和关系要在一个空间里演 | 常规计数、柱图、折线先选[现成 Remotion 组件](motion-frameworks.md#先找现成组件)。节点里打开原件再回到关系网、人物压在巨字前面等连续动作，可用已有路线、因果链、新闻桌面和分层人物场景。场景名、参数、何时值得用由本机实际注册表提供。普通场景拼不出特定机制时可用项目自绘 JS；其帧号来自同一节目时钟。[可渲染的场景与自绘入口](explainer-scenes.md) |
| 两个镜头需要共用对象 | 图卡倒成桌面、推穿指定实物、从节点展开证据窗并收回，用正片原生转场；同一数字跨过几刀则固定在节目层，底下可以换实拍。[三个空间转场](spatial-bridges.md) · [跨镜固定图层](picture-edit.md#把同一对象留在换镜前后) |
| 主持人讲解或把图挂在墙上 | 导入录音与实际台词，主持全屏、变景别、墙卡、身后换景、圆窗、竖窗和回房间均可按词排。无出镜素材时也可用本地见秋声线或自备分句录音驱动相同的词时钟。[口播、原声插段与人物画面](explainer-presenter.md) |
| 让动画、字幕、声音协作 | 近景字和背景颜色按实际证据决定。重点读数时让另一层先退，拟音锚在实际接触、位置改变或数字落定的帧。导出继续走本地色彩、混音、署名和横竖版重排。[分层运镜](motion-direction.md) · [背景音乐与分轨](screen-and-mix-review.md) |
| 查错和跨片复盘 | 从正片看全片节奏；候选报告会列出读数驻留、方向和切点、几乎整块纯色的画幅，以及引文和邻句的实际响度。再按源显示时间戳回看关键动作的连续帧。[逐帧复核](story-sound.md#带时间码拆片) |

模板的参数检查会提示漏填字段、取景和阅读时间。相邻几镜做了同一手法，要回看它有没有在解释新的关系。画面里只有一帧漂亮、前后观众却找不到对象时，应改镜头起点和承接物。以前的片长、配色、出镜比例或推拉次数只用来生成复看问题。一次真实的停顿可能比下一刀更能说明人物的反应。

## 对照两期用过的实际动作

在工程目录运行。该命令读取本期准备好的时间线，对模板逐帧求动作，对原生转场读取实际剪辑声明。输出的时间以全片帧为准。制作中可用 shot 的 `transition_reason`、`visual_reason` 说明原生动作服务于哪一处发现；模板镜头用 `says` 或自绘动作自己的 `why`。

```sh
"$PY" "$SK/scripts/explainer_direction.py" --project . --out qa/direction.json
"$PY" "$SK/scripts/explainer_direction.py" --project . --previous ../last/qa/direction.json
```

`shared_in_order` 是两期按原先顺序能对应上的动作个数，同一动作出现两次会分开计算。连续重复或很高的重合度提示具体回看哪几镜。品牌的固定动作为何复用、这一次换物体的走法是否更清楚，由导演在看到画面后决定。全片的 `flat_picture_candidates` 是近纯色主体区的帧区间，核对原件和字幕是否因为文件缺失而消失，也允许确有叙事作用的留白。

`presenter_staging` 按实际显示帧统计房间、圆窗、竖窗、离场、未标注各占多少帧和多少秒，`off_screen_runs` 列出跨镜头连续离场的首帧与结束边界，区间不含结束帧。统计依据是场景编排，普通实拍记为未标注，窗形过渡随新场景归类，人物在成片里是否可见、何时该回来须回看对应帧。

## 三个案例分别用来学什么

- 《AI 到底有多烧钱》用同一笔金额串起标题、分流、实拍、关系图和收支差。原文件的公开 GIF 展示前 29 秒，其后的镜头从导演表和实装代码核对，制作新片时要用本期自己的证据重建。 [无人出镜案例](https://github.com/HeyChengC/wallstreet-explainer/tree/f39845abd45dab3c9ce62587aa5d02f6afe82612/examples/ai-burn-money)
- 《打仗了，黄金为什么反而跌》用同一段主持原声把人物在房间、视窗、图板和原文之间接起来。可在公开 GIF 逐帧察看窗形变换，声音布点从其配置核对。[主持人案例](https://github.com/HeyChengC/wallstreet-explainer/tree/f39845abd45dab3c9ce62587aa5d02f6afe82612/examples/gold-rates)
- 《谷歌给苹果的两百亿》从一次具体操作讲到付款关系、证据和换算，结尾回到最初入口。库中发布了镜头表和 HTML，案例原片与第三方素材未随附。新片可借这种首尾呼应，也可借其返修经验，在最终分辨率查末段是否意外变成空画。[手写案例](https://github.com/HeyChengC/wallstreet-explainer/tree/f39845abd45dab3c9ce62587aa5d02f6afe82612/examples/google-apple-20b)

## 录音之前先排静态分镜

写好 `edit.json` 的 `shots[].lines` 和 `explainer_scene.scenes` 后，可以先检查画面能否接上。预排读取实际念法 `line.spoken` 或字幕正文，按汉字、数字、英文单词和句内停顿估时。作者已试读某句时，用 `"estimate_seconds":2.6` 填这句话的预计朗读秒数。已有原声插段直接用它的源入出秒数。镜头和句间的 `lead`、`pause`、`tail` 继续生效。纯画面三秒可写 `"lines":[],"lead":0,"tail":3`。

```sh
node "$SK/scripts/explainer_board.cjs" --project . --shot energy --check
node "$SK/scripts/explainer_board.cjs" --project . --shot energy --frame 18 --png qa/energy-F18.png
node "$SK/scripts/explainer_board.cjs" --project . --shot energy --sheet qa/energy-board.png
```

同一个词在一句里出现两次时，`@句id:词#2` 用第二次出现的位置。检查和静态图都使用本镜真实的场景与素材，联系表的每一行是该场景首、中、末三个显示帧。估算时钟只在内存中使用，输出标有 `clock: estimated`。录音到位后正常执行 `prepare.py` 和 `explainer_scene.cjs`，同样的词锚点会在实读时间上重新求值。
